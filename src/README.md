# AIAC — AI Agents Core

> Название рабочее. Варианты на замену, если захотите другое: `crew-kit`, `agent-forge`,
> `architect-executor`, `pair-protocol`. Переименовать — просто переименовать папку и поправить
> ссылки на неё в `CLAUDE.md`, ничего больше не завязано на конкретное имя.

Переносимый скелет процесса разработки через связку **умный оркестратор (Claude) + дешёвый
объёмный исполнитель (агент с большим контекстным окном, по умолчанию — opencode)**. Извлечён из
реального проекта [MeetingTranscriber] после того, как этот процесс сложился на практике, включая
все найденные болевые точки — это не абстрактная теория, а рабочая методология, проверенная на
десятке реальных раундов задач.

## Философия в двух абзацах

Один агент (Claude) держит в голове architecture-level картину: зачем это всё, что уже сделано, что
дальше, какие есть риски, какие решения приняты и почему. Он **не пишет код объёмными раундами сам**
— он формулирует ровно одну задачу за раз с явными критериями готовности, запускает исполнителя,
**никогда не доверяет его самоотчёту**, независимо проверяет результат (пересборка, тесты, ручной
запуск) и только после этого продвигается дальше.

Другой агент (исполнитель, по умолчанию opencode с контекстным окном ~1M токенов) не хранит в себе
архитектурную картину — он получает предельно конкретную задачу, реализует её, отчитывается через
три файла, коммитит. Он не принимает архитектурных решений сам — если задача сформулирована с
развилкой, оркестратор обязан явно указать предпочтительный вариант, а не оставлять выбор
исполнителю (это отдельно найденная на практике необходимость — неявные развилки решаются
непредсказуемо).

## Структура этой папки

```
aiac/
├── README.md              — вы здесь
├── VERSION                 — версия протокола (semver); при бутстрапе штампуется в CLAUDE.md проекта
│                             как {{AIAC_VERSION}}, чтобы будущие сессии могли заметить, что aiac/
│                             в подключённом проекте обновился с версии, на которой делали бутстрап
├── BOOTSTRAP.md            — протокол первого запуска протокола в проекте — с нуля или на уже
│                             существующем коде, инструкция для Claude (см. Шаг 0 внутри)
├── LESSONS_LEARNED.md      — конкретные баги/уроки с реального проекта, обобщённые в принципы
└── templates/              — шаблоны файлов-протокола, с плейсхолдерами {{...}}
    ├── CLAUDE.template.md   — копируется в корень НОВОГО проекта как CLAUDE.md первым делом
    ├── AGENTS.template.md   — протокол для исполнителя (универсальная часть + место под технику проекта)
    ├── PLAN.template.md     — skeleton плана (архитектура/roadmap/статус) — контент появится в интервью
    ├── CURRENT_TASK.template.md — формат файла задачи; живёт в `tasks/{pending,in_progress,done}/`
    │                             проекта, не в корне (названо не `TASK.template.md`, чтобы историческая
    │                             причина из `aiac/LESSONS_LEARNED.md`, пункт 10, не повторилась)
    ├── STATUS.template.md
    ├── LOG.template.md
    ├── REPORT.template.md
    └── ADR.template.md      — шаблон Architecture Decision Record, копируется в docs/adr/NNNN-*.md
                                проекта для нетривиальных технических решений (см. PLAN.template.md)
```

Имя папки — именно `aiac/`, это не украшение: шаблоны и `BOOTSTRAP.md` ссылаются на эти файлы
поимённо (`aiac/BOOTSTRAP.md`, `aiac/LESSONS_LEARNED.md`, `aiac/templates/…`), и установщик
(`install.sh` в корне репозитория, не в `src/`) кладёт протокол именно сюда. Переименуете папку —
сломаете все эти ссылки разом.

## Как это использовать

### Шаг 0 — поставить протокол в проект

Одна команда из корня проекта:

```bash
curl -fsSL https://raw.githubusercontent.com/zeroscrypt/aiac/main/install.sh | bash
```

Установщик кладёт **содержимое `src/` в `<проект>/aiac/`** (имя папки именно `aiac` — протокол
ссылается на неё поимённо, см. все упоминания `aiac/…` в шаблонах ниже) и создаёт
`<проект>/CLAUDE.md` из шаблона, если такого файла ещё нет. Больше он ничего не трогает: если
`CLAUDE.md` уже есть — оставляет его в покое и говорит об этом (см. пункт 2 ниже).

Полезные флаги: `--dir <путь>` (каталог проекта, если он не текущий), `--ref v1.6.0`
(зафиксировать версию протокола вместо `main`), `--force` (обновить уже установленную папку
`aiac/`, например после обновления протокола), `--no-claude` (поставить только папку `aiac/`
и не создавать `CLAUDE.md` вовсе). Полный список — `bash install.sh --help`. В Windows без WSL или
если выполнять код из сети не хочется — установка вручную:

```bash
cp -R path/to/aiac/src ./aiac
cp aiac/templates/CLAUDE.template.md ./CLAUDE.md
```

### Шаги 1-3 — запуск

Работает для двух разных ситуаций — заводите ли вы проект с нуля, или подключаете этот процесс к
уже существующему, живому репозиторию. Разница вся — внутри интервью на Шаге 2 `BOOTSTRAP.md` (сам
Claude определяет, какой это случай, на Шаге 0); подготовка снаружи одинаковая:

1. Проект с нуля — создайте пустую папку. Проект уже существует — просто откройте его корень.
2. **Убедитесь, что Шаг 0 отработал:** в корне проекта лежит папка `aiac/` с этими файлами и есть
   `CLAUDE.md`, скопированный из `aiac/templates/CLAUDE.template.md` (пока он содержит плейсхолдеры
   `{{...}}` — заполнит их бутстрап, это нормально). Если ставили протокол вручную, а не
   установщиком, — скопируйте шаблон под именем `CLAUDE.md` сами: это единственный обязательный
   шаг руками. Всё остальное Claude сделает сам при первом запуске (см. `BOOTSTRAP.md` —
   `CLAUDE.md` на него сразу сошлётся).
   - **Если в проекте уже есть свой `CLAUDE.md`** (от предыдущей, не связанной с `aiac` работы) —
     **не перезаписывайте его не глядя.** Установщик в этом случае его не трогает и говорит об
     этом вслух; сохраните его в сторону (например, `CLAUDE.md` → `CLAUDE.orig.md`) и скажите об
     этом Claude в первом же сообщении при запуске — он учтёт его содержимое при интервью вместо
     того, чтобы молча его потерять.
3. Запустите `claude` в этой папке. Он прочитает `CLAUDE.md`, увидит, что `PLAN.md` ещё нет — значит,
   этот процесс здесь ещё не заводили (это не то же самое, что «проект пустой», см. `BOOTSTRAP.md`,
   Шаг 0), — и перейдёт к `aiac/BOOTSTRAP.md`. Если проект с нуля — проведёт с вами интервью про
   замысел, стек и первую точку ценности. Если проект уже существует — сначала сам изучит код,
   покажет вам черновик того, как понял архитектуру и текущее состояние, и попросит подтвердить или
   поправить, прежде чем спрашивать про следующую задачу. В обоих случаях — **не будет ничего
   выдумывать там, где неясно**, спросит явно.
4. По итогам появятся настоящие `PLAN.md`/`AGENTS.md`/первая задача в `tasks/pending/0001-*.md`
   (или без неё, если для существующего проекта пока нет готовой первой задачи) — про ваш конкретный
   проект, а не шаблонные заглушки — и работа пойдёт по протоколу из `AGENTS.md`.

## Как обновить протокол в уже подключённом проекте

Протокол развивается, и рано или поздно в подключённом проекте окажется старая версия. Механизм
этого обнаружения встроен: `VERSION` в этой папке при бутстрапе штампуется в `CLAUDE.md` проекта
как `{{AIAC_VERSION}}`, поэтому при следующем запуске Claude сам увидит, что версия в `aiac/VERSION`
новее — и по правилу из `CLAUDE.md` не станет переносить изменения молча, а спросит вас.

Чтобы обновить сами файлы папки `aiac/`:

```bash
curl -fsSL https://raw.githubusercontent.com/zeroscrypt/aiac/main/install.sh | bash -s -- --force
```

`--force` заменяет только папку `aiac/` и **не трогает** `CLAUDE.md`: в нём остаются реальные
значения, подставленные вашим бутстрапом, — потерять их из-за обновления протокола нельзя. Сама папка
`aiac/` протоколом никогда не редактируется (она справочник), так что замена безопасна, но перед
ней стоит убедиться, что своих правок в ней нет: `git status --short`.

Закрепить версию вместо `main` (воспроизводимое состояние проекта) — `--ref v1.6.0`; полный
список флагов — `bash install.sh --help`.

## Откуда это взято

Проект-пример: MeetingTranscriber (macOS-приложение для локальной транскрибации звонков). Полная
живая история процесса — в его собственных `PLAN.md` (раздел «6. Продакшен-готовность» = пример
того, как выглядит зрелый живой план), `AGENTS.md`, `REPORT.md` (десятки раундов реальной работы,
включая найденные и исправленные баги самого процесса — см. `LESSONS_LEARNED.md` в этой папке для
выжимки).
